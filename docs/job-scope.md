# 发布任务按发起人筛选（OPS 0.6.10）

前端默认「我的任务」，可切换「团队全部」，支持具体商城连接和状态组合筛选。服务端统一在计数和分页前筛选，保持owner边界，直接按登录sub筛选，不接收客户端指定任意发起人。

独立job_initiators表记录实际提交任务的账号及显示名，与jobs和快照在同一事务中写入。发起人不同于商品采集人；重试、回调、核验不改变发起归属。原任务状态、token、claimed、快照和商城商品ID不变。团队协作权限不变，只是列表视图。

历史任务从个人owner、团队job.create事件和个人job.create审计恢复；不能确定的在团队全部中显示「历史发起人未知」。个人迁入团队保留归属。API缺省scope仍为all以兼容，前端明确请求mine。任务商城筛选使用连接ID以区分同一系统的不同商城。

更新OPS即可，无需更新n8n、商城或采集插件。170项测试通过，涵盖成员边界、不同工作空间、商城和状态组合、分页、历史迁移，以及团队中他人商品由当前发布账号发起的handler流程。
