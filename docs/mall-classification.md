# 商城现有商品分类与标签整理（CRMEB Pro 4.3）

适用于小蓝优品对应的 **CRMEB会员商城** 连接。以 OPS 中实际系统类型和商城网址为准，不能仅凭可修改的商城名称判断。多门店、Tigshop、芸众暂不支持此功能。

## 能做什么

- 菜单“商城商品整理”：搜索、分页读取平台自营主商品，包括上架与下架商品；无需原来由OPS创建或关联。
- 按当前页选择最多50件商品，分类可保留或替换为多个已有商城分类；商品标签可保留、追加、移除或替换。替换时空选择代表清空。
- 显示修改前后的分类及标签，确认后将任务写入SQLite持久队列，独立Worker按商品执行并读回核对。
- 记录原值，成功项可生成回退预览，再次确认才会执行。原分类为空的商品不能直接回退到空分类。
- 创建分类、创建标签和AI自动分类不在本版范围；先在商城后台建立讨论确定的分类和标签，再在OPS中选择。

## 为什么需要商城专用接口

官方商品保存接口包含大量默认值，不适合仅更新分类和标签。本版增加四个受现有 outapi Token 和逐接口权限保护的专用接口：

| 方法 | 路径（不含 /outapi） | 用途 |
| --- | --- | --- |
| GET | /ops-classification/catalog | 平台分类和商品标签字典 |
| GET | /ops-classification/products | 商品分页列表，每页50件 |
| GET | /ops-classification/product/:id | 商品分类标签读回 |
| POST | /ops-classification/product/:id | 仅分类与商品标签更新 |

只更新 store_product.cate_id 和 store_product.store_label_id，并在同一事务中同步原生标签关联表。使用行锁和修改前快照对比，拒绝覆盖其他人的分类标签变更。清理原生商品缓存；不调用整商品保存、创建或上下架接口。

## 部署前准备

1. 备份商城数据库及代码，确认小蓝优品对应的实际会员商城PHP根目录与版本。
2. 推送并部署OPS（包含这些新增文件）。`OPS_DURABLE_QUEUE` 必须启用，Worker须健康。
3. 在安装OPS源码的服务器执行，替换实际商城路径和PHP二进制路径；以下第一条只检查，不写商城文件：

```bash
cd /www/wwwroot/mainapis-ops
python3 scripts/patch-crmeb-classification.py --root /实际/会员商城PHP根目录 --php /www/server/php/82/bin/php
```

检查成功后执行安装。脚本先对两个候选文件运行 PHP 语法检查，全部通过才备份并写入；失败不写，重复安装原样跳过，同名未知内容拒绝覆盖。

```bash
python3 scripts/patch-crmeb-classification.py --root /实际/会员商城PHP根目录 --php /www/server/php/82/bin/php --apply
cd /实际/会员商城PHP根目录
/www/server/php/82/bin/php /www/wwwroot/mainapis-ops/scripts/register-crmeb-classification.php
```

登记脚本只增加接口元数据，不为任何账号自动授权。请在商城后台“对外接口”中核对OPS现有应用，为上述四个接口分别授权；只读试用时只授予三个GET接口。

4. 在OPS选择正确商城连接，读取字典和商品。如没有权限或接口缺失，页面会明确报错，不回退到整商品保存接口。
5. 先用1件可核对商品完成“预览 → 确认 → 读回成功 → 商城后台核对”，再验证回退，最后扩大批量。真实商城写入尚未验收。

## 运行与异常处理

- 编辑成员可读；审核员及管理员可以预览、确认、核对与回退。所有记录按工作空间和商城隔离，修改请求沿用会话、Origin和CSRF校验。
- 预览30分钟有效。过期或商品已变化时重新读取并预览；预览本身不会写商城。
- 提交接口仅排队，避免把商城写入长时间放在浏览器请求中。排队/执行记录不可重复创建同商品并行任务；重复确认同一记录不重复入队。
- 网络错误、响应丢失或Worker中断均保留待核对，不自动重发。Worker中断遗留的执行项超过120秒后转待核对。点击“只读核对”检查实际结果。
- 已应用则标成功；仍为原值则标未应用；其他值则标冲突。未应用项可以重新读取生成新预览，不绕过快照校验。
- 回退也检查当前值仍等于这次修改结果，否则拒绝覆盖后续修改。
- 商品价格、SKU、库存等可由商城其他业务独立变化；本流程不写这些字段。

## 验证范围

本地测试使用合成商品及模拟商城接口，覆盖：预览不写、字段白名单、标签模式、工作空间及角色权限、CSRF、重复提交、任务碰撞、超时后只读核对、Worker中断、并发变更、读回ID不符、商城地址变更及回退。

本地没有PHP解释器，商城安装脚本会在服务器PHP解释器下强制语法检查。PHP接口实际数据库事务、商城缓存及授权需在目标版本完成单件联调后验收。
