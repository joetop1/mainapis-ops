# 加密异地备份和运行告警（0.17.0）

默认关闭。现有本地备份照常执行；启用后，每次生成并校验本地备份，再将数据库、原连接解密密钥、校验清单一起压缩，用独立32字节密钥执行AES-256-GCM认证加密，上传共享OSS的`ops-private/backups/`目录。上传设置private对象ACL，并读回核对私有权限、长度和SHA256后才记为异地成功。本地和异地成功状态分开，上传失败不否定本地备份；自动备份开启时，异地失败最早一小时后重新生成并尝试。

## 一次配置

1. 使用现有共享OSS配置；给OPS的RAM凭证增加`oss:PutObject`、`oss:GetObject`、`oss:GetObjectAcl`，仅授权`acs:oss:*:*:mainapis/ops-private/backups/*`。不要改变图片目录权限。
2. 给`ops-private/backups/`单独设置30天清理生命周期（可按需求调整）。不要应用货盘原件的一天清理策略，也不要对`ops/`商品图片目录设置到期删除。
3. 在可信终端运行`openssl rand -base64 32`生成一次独立密钥，保存到密码管理器或离线安全位置。不要将密钥提交Git、发聊天或只留在服务器。它与connections.key不同，不能相互替代。密钥丢失无法恢复；更换密钥时仍需保留旧备份对应旧密钥。
4. 编辑服务器`.env`：

```dotenv
OPS_OFFSITE_BACKUP=true
OPS_OFFSITE_ENCRYPTION_KEY=此处填写生成的Base64密钥
OPS_OPERATIONS_WEBHOOK=此处填写专用企业微信群机器人地址
```

告警为可选项，不使用时留空。保存后重新创建完整Compose项目：

```bash
docker compose up -d --build
```

5. 系统设置 → 运行保障 → 立即备份，等待本地和异地状态都显示成功。上线验收应下载一次加密对象，在安全位置完成离线解密验证。本地测试模拟了OSS，不代表实际RAM、网络和Bucket配置已验证。

## 恢复演练

从OSS控制台下载`.opsenc`到安全环境，设置对应的`OPS_OFFSITE_ENCRYPTION_KEY`环境变量（不要写入命令历史里的明文参数），用项目代码运行：

```bash
node offsite-backup.mjs --decrypt /安全路径/备份.opsenc /安全路径/全新恢复目录
```

命令只写新目录，不覆盖已有目录，不操作运行数据库。先验证GCM认证、清单文件范围、各文件SHA256和SQLite quick_check，再报告验证结果。解密失败、文件篡改不会提交恢复目录。解密目录包含原数据库和连接密钥，请按敏感资料保管。

真正替换运行数据前，按operations.md的停机步骤操作，必须先设置`OPS_WORKER_PAUSED=true`。旧备份可能把已在商城执行过的任务恢复成未执行状态，必须核对队列与商城/n8n记录，禁止直接启动Worker消费旧队列。不要混入旧WAL文件。

`.env`、独立异地加密密钥、未完成货盘预览及OSS商品图片本体不在数据库备份中，需分别保管。当前归档原始文件总量最多256MB；超过时保留本地备份并报告异地失败，需要进一步调整容量方案。

## 运行告警

网页进程每分钟检查：就绪异常、数据盘不足2GB、Worker心跳超时（启动180秒后且非暂停）、本地或异地备份失败、超过30分钟未结束的发布任务。仅发送固定业务摘要，不含商城凭据、令牌、备份内容或个人资料。

同一监控实例最多一小时发一次，持续故障每小时提醒，恢复也受此限频；发送状态持久保存，失败一小时后重试。暂停Worker不会触发Worker离线告警。此功能不自动重启服务、取消任务、释放领取锁或重新创建商品。

整机宕机、网页进程完全退出或整机网络中断时，本机不能发出告警，需要外部监测`/readyz`；站内告警不是外部可用性监控的替代。共享OSS的异地副本可防本地磁盘丢失，但不等于跨云账号灾备；更高要求应使用独立账号/地域及额外副本。
