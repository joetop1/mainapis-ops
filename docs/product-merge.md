# 多链接合并为多规格商品

OPS 0.8.1。适合上游把同一商品的不同型号、颜色或容量分散在多个1688链接中的情况。

## 操作

1. 把各链接采集进采集箱，每条必须已经有SKU、成本、售价和库存。
2. 勾选2至20条商品，点击「合并为多规格商品」。支持在已加载记录中跨分页选择，切换「我的采集/团队全部」会清空选择。
3. 选择主商品，填写合并标题与规格维度名称（如型号）。
4. 核对每个来源SKU的合并编码和规格值。两者分别不能重复；原始来源编码不被改写，另行留存。
5. 选择主图、详情图保留方式，点击「预览并检查」。
6. 确认后点击「生成合并商品」。生成一条新的待整理商品，并自动打开编辑页。
7. 整理共用详情和参数，检查图片、价格和所有规格，核对各商城映射，保存后重新审核，再按原流程发布。

主图默认汇总所选商品并去重，主商品图片排前面；详情图默认仅取主商品，可改为汇总。
超过30张主图或100张详情图时明确报错，不静默裁剪，可先选择仅主商品，再在编辑页补充整理。
标题、文字描述、产品参数、商城映射、CRMEB标签和虚拟销量取主商品，不拼接互相矛盾的基本信息。
每个来源SKU的成本、售价、库存和配图独立保留，缺少SKU图片时使用其来源商品首图。
合并后上游链接、原SKU编码、原规格文字、来源记录ID和版本分别保存在SKU来源中。
编辑页可展开各SKU的原链接，SKU编码下也有来源链接。合并商品支持按任意SKU来源URL搜索。

此版本将所选记录的每个SKU明确整理为一个规格维度：原多维规格只供对照，不猜测跨链接颜色/尺码关系。
所有来源SKU必须包含在合并预览中；多余SKU可生成后在编辑页人工删除。总计最多500个SKU，各商城仍按自己的发布上限校验。
只适用于同一款商品的变体；不同商品套装、混合商品、组合库存和上游库存同步不属于此功能。
手工新加的SKU没有自动来源，原有SKU的来源在编辑和规格重排中保留。

## 原记录与已发布商品

原商品的内容、版本、审核状态、发布任务及商城商品保持原样。
如果所选原记录已有发布任务，预览明确提醒：本次仅合并OPS资料，不会合并或更新商城中的现有商品。
后续发布新合并商品可能在商城形成另一款商品，需要人工核对原商城库存及上下架安排。
新记录初始为待整理，不继承主商品的审核通过状态、商品ID、发布成功记录或创建领取锁。
只有在重新审核并主动提交发布任务后，才使用原有连接器的下架入库流程。

## 保存、重试与权限

合并预览不写商品，也不调用上游或商城接口。创建时再次检查各源记录版本和当前工作空间归属。
写新记录、采集归属、审计和幂等回执在同一事务内，失败整体回滚。
接收请求结果不明确时可点击「重试确认同一次合并」，使用同一请求编号查询结果，不重复创建。
同一设置的重复提交返回同一新商品。成功后即使原商品后来被修改，同一请求也仍返回已创建的合并商品。
个人工作区迁入新团队时一并迁移合并回执；其他工作空间无法使用源记录或读取回执。
团队编辑可以合并资料，但仍无审核/发布权限。新商品记录归属实际发起合并的人，继续遵循采集范围筛选。

数据库内部为合并记录分配独立的唯一来源身份，展示及SKU溯源仍使用真实1688链接，不虚构商品链接。
原1688链接再次导入仍按原记录去重，不会覆盖合并商品；不会自动追踪或更新上游价格与库存。

## 验证

自动测试覆盖四链接合并、编码/规格冲突、重复原始SKU、图片限额、嵌套溯源、事务回滚、源版本变更、
重复请求、权限隔离、团队迁移、已发布提醒、重新编辑与旧客户端保留来源，以及本地表单状态和SKU读取。
未执行真实商城创建；合并后的多商城发布仍需按原流程核验。
