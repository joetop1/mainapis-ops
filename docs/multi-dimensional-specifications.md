# 多维度商品规格

之前只有 skus[].spec 显示文本，发布时所有组合统一写进“规格”一个属性中。新版保留 spec_names 与每个 SKU 的 spec_values。例如：

```json
{
  "spec_names": ["颜色", "尺码"],
  "skus": [
    {"sku":"ALI-1", "spec_values":["红色","M"], "spec":"红色 / M", "price":20, "cost":10, "stock":5},
    {"sku":"ALI-2", "spec_values":["红色","L"], "spec":"红色 / L", "price":25, "cost":11, "stock":6}
  ]
}
```

最多5个维度，每个SKU值的数量必须与名称一致，组合不能重复。不会根据选项自动补造笛卡尔积或不存在的SKU。本来只有一个维度的商品仍只有一个维度。

## 使用与更新

1. 更新 OPS 服务器。
2. 从“连接与配置”下载采集助手0.1.9，替换原插件目录文件，扩展管理页点击重新加载。
3. 重新采集源商品；预览分别显示 SKU 数量与规格维度数量。页面提供完整属性名时保留颜色、尺码等；缺少名称但组合明确时使用“规格1、规格2”等，需核对命名。
4. 新商品直接导入。OPS 已存在的商品，在编辑页选择“导入重新采集的规格结构”，按来源与SKU编码补回维度，价格、成本、库存和配图保持当前值；SKU数量或编码不同则整批拒绝，不覆盖。
5. 编辑页“规格维度名称”填颜色、尺码等，用逗号分隔，点击“应用规格列”。表格按维度显示独立输入列。调整顺序按名称映射原值，新维度需要填写值；旧合并文字只作参考，不按斜杠猜拆。
6. 核对各SKU、保存并重新审核。

## CRMEB 现有工作流

会员商城：

- “配置分类运费并转换字段”替换为 workflows/crmeb-member-prepare-template1.js。
- “核验实际入库结果”替换为 workflows/crmeb-member-verify.js。

多门店：

- “配置分类运费并转换字段”替换为 workflows/crmeb-store-prepare-template1.js。
- “核验实际入库结果”替换为 workflows/crmeb-store-verify.js。

两份独立准备代码仍保留此前确认的运费模板1。只替换上述代码节点并Publish，不修改已接入OPS的获取Token节点、凭证或其他节点，不导入整份新工作流覆盖线上配置。

独立属性组映射到 items，各 SKU 的独立值映射到 attr_arr 和 detail；核验按全部维度检查。可使用 `node scripts/build-crmeb-node-snippets.mjs` 从源模块重新生成这四份代码。

## Tigshop

随OPS后端更新自动使用多组 attrList.spe，各SKU的attrs分别列出维度，并按实际返回的skuData核验。EUR换算、库存与运费逻辑保留。Tigshop配图依附属性值，同一首级规格如果有冲突配图会在创建前拒绝，需统一该规格图片或调整规格维度顺序；不静默选择任意图片。

## 既有数据

旧商品及不可变的发布快照不自动迁移。没有独立结构的旧文本保持旧单列模式，可重新采集后在编辑页补回。已发布商品不会被这次更新自动修改；在商城后台核对修改，不能为同一任务重复创建。

本地测试覆盖二维、三维结构、采集ID映射、保存、重新采集导入、两个CRMEB准备与核验Code沙箱及Tigshop映射。真实页面布局与商城入库仍须以实际商品核对为准。
