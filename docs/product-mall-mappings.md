# 商品多商城映射与一次提交

OPS 0.8.0。商品编辑仍使用原弹窗，标题、图片顺序、详情、产品参数、SKU、成本、售价、库存和虚拟销量共用。
新增「商城分类与品牌」区域，显示各实际商城名称。选中一个商城设置其分类、品牌，CRMEB标签及多门店适用范围也分别保存。
可来回切换，未保存的选择保留在本次弹窗中；点击「保存商品」才持久保存。关闭弹窗放弃未保存的修改。
旧商品的原分类、品牌只归属其原商城，首次编辑时保留；不会自动把旧ID复制给另一商城。
不同系统、同系统不同连接均使用稳定连接ID区分，不按商城名称或分类文字匹配。

## 操作

1. 编辑商品，分别为需要发布的商城选择分类、品牌（品牌可不设置）。
2. 保存商品，核对共用资料和各商城映射，审核当前商品版本。
3. 点击发布，勾选一个或多个已配置商城，一次提交各自的下架入库任务。
4. 提交窗口分别显示每个商城的任务创建结果。尚未创建任务的失败项可单独重试；成功创建的项自动取消勾选并锁定。
5. 发布任务页查看每个独立任务的执行及实际商城核验结果。任务创建成功不是商品发布成功；仍按原连接器要求核验。

修改任何共用资料或映射都使商品进入待整理并增加版本，需要重新审核。
可以先保存未完成的商城映射，但该商城不能发布；审核至少需要一个已选分类，实际提交仍逐目标检查。
已有发布任务（包括历史成功、待核对）在选择窗口锁定，避免无意重复创建；失败的执行任务在发布任务列表处理原任务。
如果提交请求中断或回执不完整，窗口停止重试，先到任务列表核对；不要用新建任务规避创建锁。
不自动更新历史已发布商品，不直接上架；分类品牌目录读取、字段/规格限制、运费模板和Tigshop汇率继续使用各连接器原规则。
会员商城/多门店旧n8n传输保持原流程，新快照仅包含该目标的映射，不需要因映射字段更新n8n代码。

## 数据与接口

商品JSON增加可选 `mall_mappings` 数组，最多50项：

```json
{
  "mall_mappings": [
    {
      "catalog_connection_id": "商城稳定连接ID",
      "catalog_target": "crmeb-pro",
      "category_id": 116,
      "category": "服饰 / 袜子",
      "brand_ids": [12],
      "tag_ids": []
    }
  ]
}
```

每个连接只能一项；所有连接须归属当前个人/团队且系统匹配。分类和品牌通过相应商城真实目录校验，目录标签由服务端规范化。
同系统两个商城使用不同连接ID，不互借ID。旧单商城字段保留为编辑页当前选择；新快照仅保留目标映射，去掉整个映射数组。
无 `mall_mappings` 的历史商品继续按原单商城校验，旧客户端更新已有映射商品时保留其他商城映射。
团队迁移延续稳定连接ID，不重写历史任务或商品来源。

`POST /api/products/:id/publish` 兼容原单商城请求；新增批量请求：

```json
{"revision": 3, "destinations": [
  {"target": "crmeb-pro", "connection_id": "会员商城连接ID"},
  {"target": "crmeb-store", "connection_id": "多门店连接ID"}
]}
```

每次1–10个、不重复的连接。返回202及 `results`，每项含 connection_id、target、ok；成功项有独立任务ID，未创建项有error。
各目标独立准备和建任务，某一目标校验失败不回滚其他目标。保存每个任务快照时再次检查商品版本和审核状态，旧版本不能晚到后创建。
沿用按连接/版本的唯一任务索引和官方创建领取锁。重试创建请求不会绕过已领取/成功任务。
缺少权限、商品版本失效等整个请求被拒绝时不视为部分结果；网络中断仍需先核对任务。

## 编辑页回到顶部

按钮在编辑弹窗内部右下角，内容滚动超过350px后出现。只滚动弹窗内容，不改变背景列表位置、不保存或修改商品。
尊重浏览器减少动态效果设置，关闭重开后从弹窗顶部开始。

## 验证

自动测试涵盖三系统独立快照、跨工作空间拒绝、重复目标与重复提交、共用修改后的审核失效、Tigshop特有校验的部分失败、
旧客户端映射保留、来回切换未保存映射、批量失败项重试和弹窗内部滚动。网络与商城写入均为模拟；真实多商城入库需线上按原任务流程核验。
