# 团队共享工作区（内部试用）

在 OPS「团队管理」输入名称创建团队。创建人自动成为管理员，当前账号的商品与发布任务转移至新团队，共享已保存的商城连接。此操作不创建商城商品，不修改任何商品快照或已领取锁。原个人连接记录保留副本；个人旧操作日志保留在原审计记录中，团队操作时间线从创建团队开始。

角色：

- 管理员：admin，全部运营权限、商城连接和成员管理。
- 审核员：reviewer，采集编辑、审核发布、任务重发与核对；不能查看或修改商城凭据和成员。
- 编辑：editor，采集、导入、整理商品，可查看团队商品与任务；不能审核、发布、重发、核对或管理连接。

权限在后端按请求校验，隐藏按钮只是界面辅助。修改角色和停用立即作用于下一个请求，不能停用或降级最后一位有效管理员。

## 添加同事

同事先拥有该 Casdoor 组织中的独立账号。在 Casdoor 找到准确的用户唯一 ID（JWT sub，一般为 UUID），管理员到 OPS 团队管理填写该 ID 和角色。这里不用用户名、邮箱、共享密码或共享登录会话。此阶段不发送邮件或站外消息。

已添加并启用的成员可以经相同 Casdoor 应用登录 OPS，不必逐个修改 ALLOWED_SUBJECTS；Casdoor 应用/组织自身的登录限制仍需允许该账号登录。新成员个人旧数据不自动合并，避免未经其操作转移私人记录。每个账号目前只属于一个团队；没有离开团队、跨团队切换或团队删除功能。

团队数据按 workspace owner 过滤，连接按同一团队 ID 加密隔离。旧商品的来源唯一性仍约束团队内不能重复采集。任务的原 ID、回调 Token、快照和领取锁均保留；因此过去的 n8n 任务继续可以回调核对。新增团队审计包含操作者的个人 sub，不只记录团队 ID。

尚无自动邀请链接、邮件邀请、Casdoor 账号自动创建、外部客户自助注册或计费。当前是受控内部团队试用，不作为公有 SaaS 多租户就绪声明。
