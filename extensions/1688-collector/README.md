# MainAPIs 1688 采集助手（试用版）

当前版本 0.1.5。初次真实页面试用发现店铺名误作标题、平台价格说明混入详情及 SKU 未识别；本版收窄标题/图片/详情范围，增加严格 JSON 页面赋值及 `skuInfoMap` 支持。尚待同一商品页重新验证，不能保证 SKU 已完整适配。

更新后在扩展管理页点本插件「重新加载」，回到商品页重新采集。如果仍为 0 个规格，点击「页面结构诊断 → 下载诊断 JSON」。诊断仅包含当前商品 ID、结构路径、字段名和 DOM 标签/类名，不导出字段值、Cookie 或账号数据；供后续针对该布局适配。

在你已登录的 1688 商品页手动采集，确认预览后导入 `https://ops.mainapis.com` 的待整理商品。图片保留原地址；不会创建商城商品，不会读取 Cookie 或要求填写 1688 密码，也不调用 n8n。无需更新服务器。

0.1.2 根据真实导出发现 SKU 名称 0–63 为数组下标，新增明确规格名称读取及拒绝下标回退；任一名称无法解析时不导入整组 SKU，避免不完整变体。已导出的 64 行成本均为 4.73，价格口径尚待页面核对，不能仅因数量相符就视为采集完整。

0.1.3 根据 755369163302 实际结构诊断，优先使用 `context.result.data.Root.fields.dataJson.skuModel`，不再让较浅的交易 SKU 数组抢占；补充 HTML 编码规格分隔符处理。预览展示前 5 个规格名称及参考成本。诊断新增所选数据路径和 SKU 行字段结构，不导出价格或商品字段值。26 项测试通过，当前页面的实际规格仍须重新采集核验。

0.1.4 支持 SKU 行图片和规格属性图片的精确匹配，新增 `skus[].image`。匹配依据为规格名称/属性 ID，冲突或缺失时不按主图顺序猜测，会明确提示。预览展示已配图/未配图和前 5 个规格缩略图。OPS 编辑页可导入重新采集的 JSON 仅补 SKU 图片，按来源和 SKU 编码匹配，不覆盖售价库存。尚需真实页面验证图片字段是否匹配。

## 安装（Chrome / Edge）

1. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
2. 打开「开发者模式」，点「加载已解压的扩展程序」。
3. 选择本文件所在目录 `goods-ops/extensions/1688-collector`（包含 manifest.json 的目录）。
4. 固定「MainAPIs · 1688 采集助手」到工具栏。

## 使用

1. 先打开 OPS 首页并完成 Casdoor 登录，保留标签页。
2. 在 1688 打开 `https://detail.1688.com/offer/数字.html`，等待规格和图片加载，展开详情、滚动加载图片。
3. 点击插件 →「读取当前商品」，核对标题、图片数量、规格及 JSON 预览。
4. 点「确认导入 OPS 待整理采集箱」。回到 OPS 点刷新，然后编辑分类、成本、售价、库存、品牌和标签。重复来源不会覆盖已有商品。
5. 确认资料后再审核、发布。没有完整 SKU 时会导入未完成草稿，不会补造规格；售价和库存固定 0，必须自行填写。识别出的采购成本可能不对应你的采购数量，须核对阶梯价和起订量。

插件仅将最后一次预览保存在本机扩展存储，关闭弹窗后可恢复。也可下载 JSON，通过 OPS 原有「导入商品资料」上传，不依赖插件直接传输。

## 已知限制与验证

- 读取页面公开商品状态和已加载 DOM，不绕过登录、验证或访问限制。页面结构变化可能导致提取不完整；试用版尚未经过真实登录态 1688 页面/浏览器端到端验收。
- 支持已暴露 `skuMap` 的页面数据结构；部分页面数据只在接口返回或详情 iframe 中，不会自动抓取，需手工补充。
- 最多 30 张图、100 个 SKU；超过 100 个 SKU 不采集规格，提示拆分。图片仅接受 HTTPS 的 alicdn.com 素材地址，不主动下载。
- 只支持当前固定 OPS 域名；导入使用 OPS 页面当前会话和 CSRF 校验，未开放跨域接口或永久 API 密钥。OPS 账号仍受服务器允许名单限制。
- 本地测试覆盖字段提取、缺失降级、规格上限、敏感字段不导出、权限范围和导入认证，不代表所有 1688 商品布局均适配。

## 使用官方采购助手

1688 官方采购助手可下载图片/视频素材和导出 Excel。OPS 现已支持把官方表格连同表头复制到「导入商品资料」，也可上传 UTF-8 CSV/TSV；不支持直接上传 XLSX。根据运营者提供的导出样例，这类表格缺少 SKU、详情和完整图片，导入后需要补充，不能直接保证一键铺货到自建 CRMEB。参见 [导入说明](../../docs/1688-import.md)。


## 商品 554 一次性后台补图

0.1.5 新增「修复已发布商品 554 的 SKU 配图」。无需更新 OPS 或 n8n，无需商城 API 密钥。它在当前已登录的 CRMEB 后台编辑表单中填写 `pic`，不请求 HTTP、不提交、不调用商品新增接口。依据提供的 Pro 4.3 编辑页 Vue 源码实现，真实线上表单仍需检查。

1. 在 `edge://extensions` 重新加载插件，确认 0.1.5。
2. CRMEB 商品列表找到 554，点击编辑，等待完整规格加载。
3. 保持该页面为当前标签，点击插件，向下展开「修复已发布商品 554 的 SKU 配图」。
4. 选择 `ops-1688-product (1).json`（已核对含 64 张 SKU 图片），点击「填入商品 554 配图（不提交）」。
5. 插件核对任务编码 `OPS-46499e8b05a944af8f9a418f7d78f2ed`、来源 755369163302、标题、全部 SKU 编码和规格名称；不匹配则整批停止。通过后检查规格图片、售价、库存，再使用商城原来的保存按钮。

该入口只用于当前已确认商品，不是通用商城更新接口。如果线上组件结构不同会明确失败，不会尝试调用保存或切换到其他商品。关闭编辑页而不保存可放弃此次图片修改。
